# 手動新增插班生

## 需求與介面

學校資料頁的上方提供「新增學生」，未選校也可使用。表單可選縣市、學校、年級及既有班級；預設帶入目前班級。可輸入姓名、綽號、男／女、年齡、身高、體重、爆發力、力量、技巧、肌耐力、體力，以及校隊身分。能力為 1～10 整數，姓名最多 40 字、綽號最多 20 字；年齡 11～17 歲、身高 120～220 cm、體重 25～160 kg。顯示班服角色、剩餘名額、學號及依 `predict100` 計算的百米預估。縣市代表、國家代表及賽事稱號沿用既有機制，不手動指定。

## 資料與雲端

保留原本的學生資料格式，額外以 `manuallyCreated`、`creationId`、`createdAt`、`seat`、`classIndex`、`admittedAt` 記錄新增來源。`worldIdentity` 及 manifest 學生數只計入原始生成學生；原本 static 快照不覆寫。

新增需要連線：先以 RTDB ETag 條件寫入保留班級中 01～50 的空座號，再將學生、學校的班級名單、校隊名單與 `student-create` outbox 一起保存到 IndexedDB。本機保存失敗則嘗試釋放保留名額。若在保留後、保存本機前關閉網頁，該座號可能保持未使用的保留狀態。同步器以一個 PATCH 新增 `dynamic/addedStudents/{studentId}`、初始綽號／隊籍及四個排名索引。若新增已存在且 creationId 相同，視為已成功，避免重試覆蓋後續成績或編輯。

雲端新增學生使用伺服器時間 `admittedAt` 建立增量索引。本機保存 `admissionCursor`；開啟網頁時只查詢該時間後的新增資料，合併至本機班級和索引。全新瀏覽器先驗證原始世界，再下載新增學生。排名及校隊讀取若遇到本機未知 ID，補取該學生，避免跨裝置漏人。所有新路徑使用既有管理者權限，固定新增個資不可覆寫。

## 比賽與保存

新學生加入現有 students、class.studentIds 及 team.memberIds，使用原有角色／個人頁／排名／比賽及 JSON 匯出流程。已啟動賽程維持既有參賽快照，後續新賽程才包含新學生。不重置任何人口、成績、稱號或自動賽程進度。

## 驗證

依使用者要求不撰寫或執行測試。執行 Vite build、JavaScript 語法及 JSON／diff 格式檢查，並檢視新增、滿班、重試、還原及跨裝置合併流程。依既有授權完成後 commit 與 push。
